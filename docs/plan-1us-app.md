# 《1 微秒》Android App 方案 · v2

> 副标题：卫星负责"量",手机负责"猜",算法负责拼整齐
> 目标：由浅到深囊括全量用户 —— 从完全不懂 GNSS 的普通人,到能读 GPS ICD 的工程师,
> 都能在同一款 App 里**亲手做出并验证**同一个结论:
> **定位精度主要由授时精度与物理误差预算决定,而不是由各家星座的"不同算法"决定。**

---

## 0. 核心命题

### 0.1 三层分工(全文主线)

| 层 | 干什么 | 谁在管 | 决定什么 |
|---|---|---|---|
| **量** | 卫星广播位置与时间,芯片测出"我离每颗星多远" | 授时精度、大气、星上原子钟、星座几何 | **精度天花板**(米级/分米级) |
| **猜** | 用卫星结果 + WiFi/基站/地图/惯导推断真实位置 | 融合算法 | **城里能不能用、漂不漂** |
| **算** | 把量到的伪距拼成坐标 | 最小二乘及其变体 | 边际收益 **< 0.1 m** |

一句话:**定位不是"算"出来的,是"量"出来的。**

量的数学几十年前就写进课本,谁都一样,没有秘方。算法的工作是把量出来的东西拼整齐——
而拼得再整齐,也超不过"量"本身的质量。

### 0.2 误差预算量级表(App 的心脏)

| 误差项 | 典型量级 | 归属层 |
|---|---|---|
| 接收机钟差(未标定) | 1 μs → **300 m** | 量 · 授时 |
| 接收机钟差(已标定) | 1–10 ns → 0.3–3 m | 量 · 授时 |
| 相对论钟差修正(不做) | 最大 ±38 ns → **±11 m** | 量 · 星上 |
| 卫星钟差残余 | 1–3 m | 量 · 星上原子钟 |
| 广播星历轨道误差 | 1–2 m | 量 · 星上 |
| 电离层(L1 单频,白天) | 2–10 m;磁暴 30–60 m | 量 · 大气 |
| 对流层(低仰角) | 10–25 m,模型后残 0.2–0.5 m | 量 · 大气 |
| 多路径(城市峡谷) | 5–50 m | 量 · 环境 |
| 星座几何(DOP) | HDOP 0.8–2 良好,>5 差 | 量 · 星座设计 |
| WiFi/基站/地图匹配 | 3–10 m(且有系统性偏差) | 猜 |
| **换更高级的解算算法** | **< 0.1 m** | 算 |

**教学核心:最后一行 vs 第一行。相差 3000 倍。**

### 0.3 诚实边界(必须明写,否则会被内行否掉)

各家在**信号结构**与**接收机算法**上的差异真实存在,且是 RTK/PPP 厘米级精度的依赖项
(模糊度固定策略、PPP 收敛策略、周跳与多路径抑制)。App 里的准确表述是:

> 算法不是没用,而是**在既定物理约束下争取最后几个厘米**;
> 它从来不是**决定米级 / 分米级差异**的那一项。
> 算法真正的价值在"猜"这一层——但前提是猜得到信息。
> 信号断了,再聪明的算法也救不回来。

### 0.4 常见误解(辟谣卡片,App 内置)

| 误解 | 事实 |
|---|---|
| "北斗比 GPS 准" | 精度差异在 0.x m 量级,日常体感不可分辨。真差异在可用性、授时服务、多频与增强体系 |
| "GPS 是军用的,所以全球都特别准" | 分水岭是**频段数量**与**增强系统**,不是哪家的算法更聪明 |
| "不依赖美国 = 更准" | 这是**安全与自主**,不是精度。这两件事被混在一起,才是大家吵不清的根源 |

## 1. 产品形态

- **纯离线,零权限,不连网**。任何手机/模拟器都能跑。
- **不用真实 GPS 硬件**。教学价值来自可复现对照——真实数据没法让同一段 10 秒换星座跑两遍。
- **真解算器 + 可控误差注入**,不是动画式玩具仿真。
- 统一随机种子体系,同场景可严格 A/B 对照。

## 2. 三层深度设计(囊括全量用户)

### 2.1 纵向:每个实验三层内容可切换

| 层 | 内容 | 语气基准 | 示例(实验 3) |
|---|---|---|---|
| **浅** | 一句人话结论 + 生活类比,无公式无单位 | 像朋友聊天,可俏皮 | 「你的表慢了 50 纳秒,地图就偏 15 米。」 |
| **中** | 定性机理解释 + 数量级(带单位,不带公式) | 像懂行的人认真解释,不装 | 「晶振有误差。光在这段时间里多走了 15 米,芯片以为卫星站得远了一点,于是把你算偏了。」 |
| **深** | 完整公式 + 推导 + GPS ICD 出处 + 可调参数表 | 像 ICD 文档,精确可溯源 | `PR = ρ + c·δt_r + Δt_rel + I + T + ε_mp + ε_n`,`c·δt_r = 299792458 × 50e-9 ≈ 15.0 m` |

### 2.2 横向:术语双开关

- **默认模式**:不出现"电离层""对流层""DOP""伪距"等术语,只说「大气里的电会拖慢信号」「卫星站的角度不好」。
- **专家模式**:全部标准术语 + 英文缩写 + ICD 章节号。

数学老师看术语毫无压力,普通人看到术语只会划走。这个开关决定了普通用户能不能走到第三层。

### 2.3 学习路径(横切)

| 路径 | 内容 | 时长 |
|---|---|---|
| **A · 三分钟速通** | 实验 0 / 1 / 3 / 6 浅层 | ~5 min,看完能用一句话讲清全片 |
| **B · 完整课程** | 全部 10 个实验,浅 → 中 | ~40 min |
| **C · 工程师模式** | 全部深挖 + 误差预算表 + ICD 对照 | 按需查阅 |

路径 A 结束时给一张**口袋卡**:三行字总结,可以直接转发给别人。

## 3. 技术方案

### 3.1 栈

| 层 | 选型 | 理由 |
|---|---|---|
| 语言 | Kotlin | Android 原生 |
| UI | Jetpack Compose + Material3 | 声明式,天空图/图表全靠 Canvas 自绘 |
| 架构 | 单模块,MVVM + StateFlow | 规模不大,过度分层是负债 |
| 数值 | 纯 Kotlin(Double 足够) | 不引 Apache Math,避免 JNI |
| 图表 | 自绘 Canvas(天空图、误差椭圆、收敛曲线、误差瀑布图) | 不引图表库,构建最稳 |
| 存储 | DataStore 存进度与实验记录 | 不引 Room,省掉 KSP |

### 3.2 仿真引擎(`sim/`)

**轨道**:按各星座真实设计参数,简化圆轨道 + 开普勒平均运动。

| 星座 | 轨道面 | 每面星 | 倾角 | 高度 |
|---|---|---|---|---|
| GPS | 6 | 4 | 55° | 20200 km |
| BeiDou MEO | 3 | 8 | 55° | 21528 km |
| BeiDou IGSO | — | 3 | 55° | 35786 km |
| BeiDou GEO | — | 5 | 0° | 35786 km |
| Galileo | 6 | 4 | 56° | 23222 km |
| GLONASS | 3 | 8 | 64.5° | 19140 km |

给定模拟历元与接收机位置,按球面几何判定可见性(高度角 > 遮挡门限),Kepler 传播算星位。

**观测生成**:对每颗可见星计算

```
PR = ρ + c·δt_r + Δt_rel + I_iono + T_tropo + ε_mp + ε_noise + b_hw

  ρ         真几何距离
  c·δt_r    接收机钟差(★ 用户主控滑块,1 μs = 300 m)
  Δt_rel    相对论钟差修正 Δt_rel = F·e·√A·sin(E),F = −4.442807633e-10 s/√m
            —— 不做这一项误差可达 ±11 m(极佳教学点)
  I_iono    Klobuchar 模型(Klint & Bjørner),TEC 由场景/太阳活动设定
  T_tropo   Saastamoinen / NICT 干湿分量 + 映射函数
  ε_mp      多路径(场景预设:开阔地近 0,城市峡谷 5–50 m)
  ε_noise   载波跟踪噪声(典型 0.3 m)
  b_hw      硬件延迟 / 相位中心偏差
```

**混合定位层(`fusion/`,对应"猜")**:

| 输入源 | 建模方式 |
|---|---|
| GNSS | 同上 |
| WiFi AP | 位置指纹库匹配,残差 3–8 m,存在系统性偏差 |
| 基站 | 三边/距离-路径损耗模型,残差 100–1000 m |
| 地图匹配 | 投影到最近道路并约束行驶方向,桥下/室内**完全失效** |
| 惯导 | 常速/零速更新,随时间发散 |

融合器:等权融合 / 卡尔曼(按场景方差自适应加权)/ 无融合。
**关键对照**:城市路口 vs 桥下——同一套算法,两种结局。信号断了,再聪明也救不回来。

**解算器**(`solve/`,对应"算"):

| 模式 | 说明 |
|---|---|
| SP 单点 | 线性化 + 迭代最小二乘 |
| 双频消电离层 | L1/L5(或 L1/L2)无组合 |
| 差分 | RTCM 类改正 + 基站位置 |
| PPP-lite | 施加精密轨道/钟差改正,观察收敛 |

**滤波器(教学高潮,同一份数据切换)**:
OLS / ILS 迭代加权 / EKF / 粒子滤波(500–2000 粒子)。
预期结论:四条曲线重合,误差差 **< 0.1 m**。

**误差分解**:逐项关闭某误差源重解,得到误差预算瀑布图。

### 3.3 场景预设

开阔地 / 城市路口 / 城市峡谷 / 桥下 / 室内 / 海岸 / 高轨,
各带遮挡角、多路径强度、TEC 基线、噪声基线、WiFi AP 密度。

## 4. 实验链

统一交互:**先下注 → 调参 → 跑 → 揭晓 → 一句话结论**。
预测承诺过的东西,才会真的被记住。

| # | 实验 | 交互 | 期望的"啊哈" |
|---|---|---|---|
| **0** | 开场 · 卫星只负责"量" | 概念页 + 交互式全景(量/猜/算三层) | 三层分工先立住,后面全部实验的坐标系 |
| **1** | 光速尺 | 时钟滑块 1 ns → 1 ms,实时误差 | 1 μs = 300 m。刻度立住 |
| **2** | 四颗星与几何 | 增删卫星、拖 DOP 椭球 | 4 颗星只是"能解"不是"解得准" |
| **3** | **星座之争** | 同一数据切 GPS/BDS/GAL/GLO/组合,再注入钟差 | 换星座误差只动零点几米;钟差 +50 ns 立刻飞 15 m |
| **4** | 多给了你料 | 单频/双频切换 + 增强广播开关 + 磁暴强度 | 双频消电离层残 0.1–1 m;增强广播再削一截。**不是数学更聪明,是多给了料** |
| **5** | **城市蓝点的真相** | 同位置切 纯GNSS / +WiFi / +基站 / +地图匹配;再切到桥下 | 城里的"准"是猜出来的;信号一断,算法立刻失效 |
| **6** | **滤波器之争** | OLS/ILS/EKF/PF 四选一 + 收敛曲线叠加 | 差异 < 0.1 m,曲线重合 ← **全 App 高潮** |
| **7** | 差分与 PPP | 切 RTK / PPP,看收敛时间 | 跃升来自外部约束与精密产品,不是更神的算法 |
| **8** | 自由沙盒 | 选场景自由配全部参数 | 多路径在城市峡谷吃掉一切;自主探索 |
| **9** | **通关挑战** | 给定场景与目标(城市峡谷要 1 m),自配参数达标 | 教以致用,形成闭环 |

**收尾 · 误差预算瀑布图**:把 3 / 4 / 6 / 7 的结论收进一张图,横向对比
「换星座 / 换算法」与「改授时 / 改大气」的量级差。

**口袋卡**:路径 A 结束后给一张三行总结卡,可直接转发。

## 6. 构建方案

沙箱现状:无 JDK / Android SDK / Gradle;Node、Python 可用。已验证可达
`dl.google.com`(200)、`services.gradle.org`(200)、`api.adoptium.net`(200)。

1. 后台装 JDK 17(Adoptium tarball)+ Android cmdline-tools
2. `sdkmanager` 装 `platform-tools` / `platforms;android-35` / `build-tools`
3. 装 Gradle 8.x,scaffold 项目
4. **先写 `sim/` + `solve/` + `fusion/` 与单元测试,用数值验收(§7)锁死物理正确性**
5. 再写 Compose UI 与三层渲染
6. `./gradlew assembleDebug` 出 APK 并交付

顺序是刻意的:数值错了,界面再漂亮也是在骗人。

## 7. 验收标准

**构建**
- [ ] `./gradlew assembleDebug` 成功,产出可安装 APK
- [ ] 安装后 10 个实验全部走通,无崩溃
- [ ] 无网络、无权限条件下完整可用

**数值正确性(单元测试)**
- [ ] 相对论钟差修正量级 ±38 ns(≈ ±11 m)
- [ ] Klobuchar 电离层延迟与教科书量级一致
- [ ] Saastamoinen 对流层天顶延迟 ≈2.3 m(静海平面)
- [ ] 钟差 1 μs → 位置误差 300 ± 5 m
- [ ] 无误差注入时最小二乘残差收敛到近 0
- [ ] 典型开阔地单点定位水平误差 3–10 m

**教学命题可复现**
- [ ] 四种滤波器在同一数据上误差差 < 0.1 m
- [ ] 同一几何下换星座误差变化 < 1 m
- [ ] 钟差 +50 ns 时位置误差 > 10 m
- [ ] 单频 vs 双频差异 5–20 m
- [ ] 城市路口:纯 GNSS > 10 m,加 WiFi 后 < 5 m
- [ ] 桥下:四种融合方式全部失效,误差 > 30 m

## 9. 风险

| 风险 | 应对 |
|---|---|
| Compose 依赖下载失败 | 依赖已验证可达;若失败降级为 Views + XML |
| 沙箱 CPU 构建慢 | 工具链安装与首次 Gradle 拉依赖放后台任务 |
| 粒子滤波性能 | 限定 500–2000 粒子,仅用于实验 6 |
| 命题被质疑"算法无用" | §0.3 诚实边界明写,讲清厘米级 vs 米级 vs 融合层 |
| 术语劝退普通用户 | 术语双开关默认关闭(§2.2) |
| "猜"层建模过于简化失真 | 明确标注为教学简化,深度层给出误差量级区间而非精确值 |
