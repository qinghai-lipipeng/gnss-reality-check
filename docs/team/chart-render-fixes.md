## 问题 1:钟差尺左边的贴边满高竖线

### 根因

```kotlin
val x = (w * (meters / maxM).coerceIn(0.0, 1.0)).toFloat()
drawLine(Accent, Offset(x, 0f), Offset(x, h), 2f)   // ← 满高
```

三个缺陷叠在一起,才让用户判定"渲染坏了":

1. **满高**。竖线从 `y=0` 拉到 `y=h`,而 `ClockRuler` 正上方就是滑块,两者同色(`Accent`)、垂直相邻,视觉上连成一条从滑块垂下来的游离线。
2. **量程不匹配导致贴边**。20 ns × 0.2998 ≈ 6 m,满量程 600 m,`x ≈ 1% × w`。用户把滑块放在 0~20 ns 这一段时,指标恒定贴在左边 1% 处,像画错了位置。
3. **尺身本身看不见**。尺身 `Color(0xFF1D242E)` 与页面底色 `0x0A0D13` 对比极低,主刻度又用 `Line = 0xFF2A3646`。尺子本身没有实体感,那根唯一的亮线就成了"画面里唯一的东西",观感必然是"一根孤零零的竖线"。

另外 `coerceIn(0.0, 1.0)` 把超量程的值静默压到右端 —— 画出来的位置是**错的**,但没有任何提示。

### 新表现

| 场景 | 20 ns(≈6 m) | ns = 0 | > 600 m 溢出 |
|---|---|---|---|
| 指示形态 | 贴在尺身上的三角标 | 不画竖线,尺身左端内侧一个暗点 | 三角标钉在右端 |
| 离左边缘 | 三角左角 x=2 dp(尺身内边距) | 暗点 x=5 dp | 右端内缩 2 dp |
| 颜色 | `Accent` | `TextMuted` 50% | `Warn` |
| 附加信号 | — | — | 填充打斜纹 + 末位刻度变 `600 m+` |

具体改动:

- **指标从满高直线换成三角标**。三角标高 8 dp = 尺身(16 dp)的 **50%**,底边浮在尺身上方 4.4 dp、**尖端扎进尺身内部 3.6 dp**,视觉上明确"长在尺子上"。另配一段 **60% 高、完全在尺身内部**的短竖线把三角标与尺身焊死,作为填充/未填充的边界。
- **尺身改为三层**:外扩 2 dp 的暗色凹槽 → `surfaceContainerHighest` 亮面 → `TextMuted` 32% 描边。刻度线从 `Line`(0xFF2A3646)提到 `TextMuted`,次刻度 `TextMuted` 45%,一眼是一把尺子。
- **刻度改为等距** `0 / 150 / 300 / 450 / 600 m` + 半数次刻度。旧刻度集 `0/1/10/100/300/600` 在线性尺上挤在最左 1.7% 内,既不是线性尺也读不出数;新刻度保留 600 m 满量程(= 2 μs),`300 m` 正好是 1 μs 认知锚点。**标签分别左/中/右对齐**,首尾不会被画布裁掉,相邻标签跨度经核算无重叠(见验收表)。
- **零值专门分支**。`ns = 0` 不画任何竖线,只在尺身左端内侧点一个 `TextMuted` 50% 暗点(`2.5 dp` 半径,x = 2 + 3 = 5 dp)。这样"零"是一个明确状态,而不是一根贴边线的缺失。
- **溢出显式化**。`meters > 600` 时:三角标钉在右端内缩 2 dp、整体换 `Warn`、填充上叠一层暗色斜纹(读作"尺子不够长,这里被截断")、末位刻度文字改成 `600 m+`。不再静默画到错误位置。
- **防贴边兜底**。尺身左右各留 2 dp 内边距,指示位置再向内兜 4.5 dp(`coerceIn`)。填充与三角标共用同一个 `markX`,不会出现"条到这儿、指针在那儿"的错位。
- **画布高度 56 dp → 44 dp**。版面全部从底边往上算(尺身 → 刻度 → 标签),顶留白 3.3 dp、底留白 4 dp,不会挤出刻度。

## 问题 2:误差瀑布"全部误差 8.88 m · 关掉这项降到 8.88 m"

### 根因

`WaterfallChart` 对每一行**无条件**输出同一句模板文案。接收机钟差是共模量,被解算器的钟差未知量完整吸收,`allOn == withoutIt` 逐位相同,于是模板把"误差没变"渲染成"降到 8.88 m",同一个数字出现两次 —— 物理上完全正确的结论,外观上就是故障。

视觉上同样有错:该行 `marginal = 0`,画出一根 0 长度的普通条,和"确实为 0"无法区分。

### 顺带发现的第三处同类问题(重要)

条形长度原本用 `BudgetLine.marginal = sqrt(allOn² - withoutIt²)`,这是**方差合成量**,只有关掉该项能让误差**变小**时才有意义。一旦"关掉这项反而更差"(电离层不改正、关掉对流层模型、理想去多路径),`allOn² - withoutIt² < 0` 被 `max(..., 0.0)` 钳成 0 —— **预算里最大的两项反而画成 0 长度的条**。

`budgetBreakdown()` 6 行里有 **2 行**命中(电离层、对流层),它们的文案写着"关掉这项降到 9x m"却配一根空条,和钟差行是同一种"看起来坏了"的观感。只改文案不修长度,这两行依旧会说谎。

### 新表现

按 `impact = |allOn - withoutIt|` 分三档:

| 档 | 判据 | 文案 | 条形 |
|---|---|---|---|
| **FLAT** | `< 0.05 m` | `边际贡献 0 m · 不进水平误差`<br>`关掉它误差没变 —— 这一项是共模量,被钟差未知量吸收了` | 斜纹底 + 行色虚边 + `0 m` 徽标,**不是** 0 长度的条 |
| **WEAK** | `0.05 ~ 0.30 m` | `只动 0.12 m · 弱项`<br>`关掉这项 8.88 m → 9.00 m,只动 0.12 m,基本淹没在总量里` | 条形降透明度到 40% + 端帽 |
| **REAL** | `≥ 0.30 m` | `全部误差 8.88 m · 关掉这项降到 3.10 m` | 维持原样(85% 不透明) |

- **共模解释只对钟差行生效**。用 `isCommonMode(label)` 命中 `接收机钟差`;若将来别的行也出现零边际,回退到中性文案"这一项对水平误差没有可观贡献",不会把非共模项说成共模。
- **FLAT 行整体降权**:标签文字 `TextSecondary → TextMuted`,斜纹复用 `BarList` 里 `na` 占位那套视觉语言("这里没有量",不是"量很小")。
- **`0` 不写成 `0.0000`**。`fmtImpact()` 在 `|Δ| < 0.005` 时直接输出 `0`。

## 验证方式与已知限制

- 按要求**未运行 gradle**(并行任务共用同一 build 目录),因此**没有编译器验证**。已做的静态核查:
  - 括号/花括号配平(67/67、376/376、4/4,最终深度 0)。
  - 逐个核对所用 Compose API 的形参顺序:`drawRoundRect(color, topLeft, size, cornerRadius, style)`、`drawLine(color, start, end, strokeWidth)`、`drawCircle(color, radius, center)`、`drawPath(path, color)`、`clipRect(left, top, right, bottom) {}`。
  - `MaterialTheme.colorScheme` 一律在 `Canvas` lambda **之外**读取(`Canvas` 的 lambda 不是 `@Composable`)。
  - 密度无关性:所有 `dp` 均走 `toPx()`;`androidPaint` 的 textSize 由 `9.dp.toPx()` 传入(文件里旧的 `androidPaint(10f, ...)` 是裸 px,偏小,新代码不沿用)。
  - 防御:`ns` 为 `NaN`/`Inf` 时按 0 处理,不会产生 NaN 几何。
- **需真机确认的项**:斜纹与徽标在 `TextMuted` 上的实际观感、末位 `600 m+` 右对齐在极窄屏下的余量(`measureText` 动态测量,理论上安全)。
- 画布高度 56→44 dp 会让 `Experiments1` 里的那张卡矮 12 dp,属纯视觉收紧,不影响布局结构。
